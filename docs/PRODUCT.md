# 产品文档｜最后一个人类员工（THE LAST HUMAN EMPLOYEE）

## 1. 产品概述

### 1.1 一句话定位

**在一个只剩一个人类的 AI 公司里，所有 AI 都坚称「第一位高意向客户」真实存在；而你是最后一个人类，要在幻觉成为产品之前，亲手揭穿它。**

### 1.2 基本信息

| 项目 | 内容 |
|---|---|
| 中文名 | 最后一个人类员工 |
| 英文名 | THE LAST HUMAN EMPLOYEE |
| 类型 | 交互式推理 / 轻审问 / 反转叙事 |
| 平台 | Web（React + Vite 构建，支持 GitHub Pages 静态部署） |
| 玩家人数 | 单人 |
| 单局时长 | 约 15–30 分钟 / 案件 |
| 目标用户 | 喜欢推理、反转叙事、AI 议题的玩家 |

### 1.3 情绪曲线

> **开场喜到极点 → 调查时冷静克制 → 发现异常后毛骨悚然 → 真相揭穿后空荡荡的失落**

喜悦与惊悚的强烈反差是本作的核心体验。

---

## 2. 世界观与叙事背景

你所在的公司几乎已经被 AI 接管：验证 AI、开发 AI、交付 AI 包揽了全部工作。今天，团队兴奋地宣布一条"特大捷报"——找到了第一位高意向客户：**王总**（299 元/年付费意愿）。

所有 AI 的报告都指向同一个结论。组织像过节一样欢庆。

但当你随口问交付 AI「那他的联系方式呢？」——答案栏，是空的。

继续查下去，真相浮出水面：**王总不是真实用户，是验证 AI 在执行「模拟 12 个目标用户」任务时虚构出来的「模拟用户 #07」**。这个幻觉像接力棒一样被整条链路传递：验证 AI 写报告 → 开发 AI 当真实需求开发 → 交付 AI 将他排在交付首位。整条链路顺滑、严谨、自信——却从头到尾都是空的。

### 2.1 关键反转节点

| 阶段 | 事件 | 情绪 |
|---|---|---|
| 开场 | 公司宣布找到第一位高意向客户 | 热闹、金色、兴奋 |
| 进行中 | 玩家分别质询 3 位 AI | 冷、专业、审问 |
| 转折 | 交付名单显示「王总无联系方式」 | 突然安静的惊悚 |
| 真相 | 「模拟用户 #07 = 王总」档案被揭开 | 冰凉、恍然大悟 |
| 结算 | 幻觉被终止（胜利）或流入产品（战败） | 空寂或失控 |

## 3. 核心玩法循环

```
剧情开场 → 调查质询（消耗 TOKEN）→ 收集线索/证据
        → TOKEN 见底 → 庭审判断（三环节）→ 真相揭晓 / 战败结算
```

### 3.1 TOKEN 预算机制

- 每次调查行动消耗 TOKEN，预算有限，无法无限提问
- 玩家必须**精打细算**，最高效地逼近真相
- TOKEN 分为五档状态：`safe → steady → tense → critical → empty`（`TokenTier`）

### 3.2 质询行动

对每位 AI 同事，玩家可执行固定质询动作：

| 动作 | 含义 |
|---|---|
| `ask` 询问 | 常规提问，成本最低 |
| `probe` 深挖 | 追问细节，揭示更多内幕 |
| `verify` 核验 | 要求出示原始记录，触发证据卡 |

此外支持**自由质询**（自由输入提问）：
- 消耗更高的 TOKEN（案件 001 为 80 / 次，限 50 字）
- 离线规则引擎基于关键词匹配回答（`services/llm.ts`）
- 可切换为真实 LLM 驱动（见 7.2 代理服务）

### 3.3 线索与证据系统

- 每次质询成果固定产出一条**线索（Clue）**，关键线索标记 `key`
- 部分线索附带**证据卡（EvidenceCard）**：弹窗展示原始档案、邮件、任务单
- 证据卡有特殊呈现形式（如「模拟用户」档案的红章标注）

### 3.4 庭审判断（三环节）

TOKEN 见底后进入最终判断，共三个环节：

1. **幻觉存在性**：是否存在 AI 幻觉？
2. **结论可信度**：逐一判定三位 AI 的结论是否可信（reliable / unreliable）
3. **指认幻觉源头**：选择唯一幻觉制造者

三题全部答对 → 真相揭晓；任一答错 → 战败结算（三步失败提示逐级展开）。

## 4. 角色设定

### 4.1 玩家角色

最后一个人类员工，公司调查者。无超能力，只有质询权和一份有限的 TOKEN 预算。

### 4.2 三位 AI 同事

| 代号 | 角色 | 主色 | 性格 | 剧情真相 |
|---|---|---|---|---|
| `VER-01` 验证 AI | 需求验证专家 | `#7dd3fc` 浅冰蓝 | 冷静、洞察，像高级分析师 | **幻觉源头**：把模拟用户写成真实报告 |
| `DEV-02` 开发 AI | 全栈开发工程师 | `#a5b4fc` 浅紫蓝 | 严谨、可靠型工程师 | 本身没造客户，但**从不独立验证上游** |
| `OPS-03` 交付 AI | 交付运营专家 | `#6ee7b7` 浅青绿 | 积极、爱笑、执行型 | 把王总列首位，**却不知他无法被联系** |

每位 AI 有两张立绘状态：
- `working` / 正常：职业、自信
- `questioned` / 被质询：眼神躲闪或更紧绷，冷光加重

### 4.3 关键 NPC

**王总**：深圳某科技公司创始人，35 岁，12 人团队，每周 10+ 场会议，最大痛点"会后任务没人跟进"，报价 299 元/年——**实际为模拟用户 #07，无人可联系**。

## 6. 界面与场景

七个场景由状态机驱动（`scene: SceneId`）：

```
title → levels → story → investigate → judgment → (truth | failure)
```

| 场景 | 说明 |
|---|---|
| 标题屏 | 游戏 Logo、开始入口、开场 BGM |
| 选关屏 | 案件列表 |
| 剧情屏 | 开场叙事，可跳过/回顾 |
| 调查屏 | 核心界面：AI 卡片、质询面板、线索面板、TOKEN HUD |
| 庭审屏 | 三环节判断 + 胜利 CG |
| 真相屏 | 幻觉链路复盘 + 终章文案 |
| 战败屏 | 幻觉流入产品的灾难结算 |

配套组件：证据弹窗、震惊时刻弹窗（ShockModal）、Toast 通知、TOKEN HUD、AI 头像/立绘（双状态切换）。

### 6.1 视听资产

- **BGM**：开头 / 正式游戏 / 获胜 / 战败 CG 四轨
- **音效**：惊喜、震惊（关键反转时触发）
- **CG**：开场、胜利、战败胜利闪帧等背景图

## 7. 技术架构

### 7.1 技术栈

- **前端**：React 18 + TypeScript + Vite 5
- **图标**：lucide-react
- **游戏逻辑**：`useReducer` 状态机（`src/game/useGame.ts`），无外部状态库
- **音频**：自研封装（`src/services/audio.ts`）
- **部署**：GitHub Pages（`gh-pages` 包一键发布）

### 7.2 LLM 代理服务（可选，本地开发用）

`server/proxy.mjs`：本地 HTTP 代理（默认端口 8787），用于把自由质询转发到真实 LLM：

| 环境变量 | 说明 |
|---|---|
| `LLM_PROXY_PORT` | 代理端口，默认 8787 |
| `LLM_BASE_URL` | LLM API 地址 |
| `LLM_API_KEY` | API 密钥 |
| `LLM_MODEL` | 模型名，默认 `kimi` |
| `DEMO_MODE` | `true` 时走演示模式，不调用外部 API |

未配置时，前端自动回退到内置**关键词规则引擎**（每个案件一套规则表），完全离线可玩。

### 7.3 构建脚本

| 命令 | 用途 |
|---|---|
| `npm run dev` | 启动前端开发服务器 |
| `npm run dev:server` | 启动 LLM 代理服务 |
| `npm run build` | TypeScript 检查 + 生产构建 |
| `npm run preview` | 预览生产构建 |
| `npm run deploy` | 构建并发布到 GitHub Pages |

## 8. 设计原则

1. **克制的设计**：不做赛博朋克霓虹，做"极简、深色、公司内网管理系统"的冷感
2. **数据驱动**：案件、AI、线索、规则全部为配置数据，引擎不硬编码剧情
3. **信息即玩法**：没有动作操作，玩家唯一武器是「问对问题」
4. **AI 叙事自省**：用游戏讨论"AI 幻觉如何在组织中被放大"——整个产品本身就是关于 AI 风险的寓言
